# Network schema

Generated by `player --project <game>.swproject --network-schema docs/NetworkSchema.md` with the arena game module, whose profiles, commands and events are listed below; don't edit it by hand. The wire format is in [NetworkProtocol.md](NetworkProtocol.md) and the guide in [Networking.md](Networking.md).

## Config/Network.swnetwork

A project without this file plays offline only. The first line is `shockwave_network 1`, then one key and value per line; `#` starts a comment. Keys left out keep their defaults. Unknown or repeated keys, values out of range and non-finite numbers are errors with file:line; nothing is clamped. Saving goes through a temporary file.

| Key | Allowed | Default | Meaning |
|---|---|---|---|
| `enabled` | 0, 1 | 0 | 1 lets the game host and join sessions; 0 is offline only |
| `transport` | steam, loopback | steam | steam (Steam networking, needs a Steamworks build) or loopback (in-process tests) |
| `steam_app_id` | 0..4294967295 | 0 | The game's Steam AppID; required when enabled with the steam transport. 480 is Valve's test app |
| `steam_required` | 0, 1 | 0 | 1 refuses to start without Steam running; 0 falls back to offline play |
| `lobby_visibility` | private, friends, public | friends | Who can find a hosted lobby: private (invites only), friends or public |
| `virtual_port` | 0..999 | 0 | Steam virtual port the host listens on |
| `max_players` | 2..64 | 12 | Players in a session, the listen host included: 2 (1v1) to 64 (32v32) |
| `tick_rate` | 60..120 | 60 | Simulation ticks per second, 60 to 120; must equal the project's tick_rate |
| `snapshot_rate` | 10..120 | 20 | State snapshots per second: 10, 15, 20, 30, 60 or 120, dividing tick_rate |
| `input_rate` | 60..120 | 60 | Input commands per second; equals tick_rate in protocol v1 |
| `interpolation_ms` | 25..200 | 100 | How far behind remote objects are shown, in milliseconds |
| `max_extrapolation_ms` | 0..100 | 100 | How long a remote object keeps moving past its last snapshot, in milliseconds |
| `max_rewind_ms` | 0..250 | 200 | How far back the host rewinds players to check a shot, in milliseconds |
| `connect_timeout_seconds` | 1..120 seconds | 15 | Seconds a connection may take to open |
| `handshake_timeout_seconds` | 1..120 seconds | 15 | Seconds from connecting to being admitted to the session |
| `idle_timeout_seconds` | 1..120 seconds | 10 | Seconds without traffic before a peer counts as gone |
| `max_replicated_entities` | 12..4096 | 512 | Network objects a session may hold; at least max_players |
| `max_snapshot_bytes` | 512..1152 | 1152 | Largest snapshot message, protocol header included |
| `outbound_bytes_per_second` | 16384..262144 | 65536 | Bandwidth the host spends on each remote peer |
| `max_pending_reliable_bytes` | 16384..262144 | 65536 | Reliable bytes queued for one peer before it counts as too slow |
| `max_receive_bytes_per_pump` | 16384..1048576 | 262144 | Bytes an endpoint reads per frame, all peers together |
| `max_receive_messages_per_pump` | 16..1024 | 256 | Messages an endpoint reads per frame, all peers together |
| `manifest` | quoted path inside the project, ending .swnetmanifest | "Config/NetworkManifest.swnetmanifest" | The network manifest (.swnetmanifest), relative to the project folder |

Rules between keys, checked by `player --check`:

- `tick_rate` equals the project's `tick_rate`; `input_rate` equals `tick_rate`.
- `snapshot_rate` is 10, 15, 20, 30, 60 or 120 and divides `tick_rate`.
- `steam_app_id` is set when `enabled 1` uses `transport steam`; 480 (Valve's test app) is a warning.
- `steam_required 1` needs `transport steam`.
- `max_replicated_entities` is at least `max_players`.
- `interpolation_ms` under two snapshot intervals (`2000 / snapshot_rate` ms) is a warning.
- `max_rewind_ms` below `interpolation_ms` is a warning.
- `max_players` records of the largest registered per-player profile, at `snapshot_rate`, fit in `outbound_bytes_per_second` minus 16384 bytes/s kept for lifecycle messages and events.

### NetworkSpawnPoint

| Field | Type | Allowed |
|---|---|---|
| `team` | integer | 0..31 |
| `order` | integer | 0..4095 |

A NetworkObject's `key` is 1..96 letters, digits and `. _ : -`, unique in its scene. The editor gives new and duplicated objects a random UUID key; a prefab root may leave it empty for its copies to set. In v1 a NetworkObject is an unparented root with scale 1 1 1, prefab parts can't be one, `always_relevant` is 1, a `PredictedCharacter` has a CharacterController and no RigidBody or Collider, and each profile's required components are present. NetworkSpawnPoint team and order pairs are unique.

## Config/NetworkManifest.swnetmanifest

```text
shockwave_network_manifest 1
game_protocol "arena.v1"
scene 1 "Scenes/arena-mp.swscene"
prefab 1 "Prefabs/Net Player.swprefab" "arena.player.v1"
```

| Entry | Values |
|---|---|
| `game_protocol` | quoted, 1..64 lowercase letters, digits and `. _ -`; bump it when C++ gameplay changes |
| `scene` | ID 1..65535, quoted `.swscene` path relative to the project |
| `prefab` | ID 1..65535, quoted `.swprefab` path inside Content, quoted registered profile |

IDs are unique per kind and never come from file order. Paths stay inside the project (no `..`, no links leading out) and must exist.

## Compatibility digests

Peers exchange two SHA-256 digests in Hello and Challenge and refuse to play on a mismatch:

- **Schema digest**: the registry below as canonical text (`shockwave_network_catalog 1`, the wire protocol version, then every profile, command and event by ID with its fields).
- **Content digest**: `shockwave_content_digest 1`, the game protocol, then every file in Content, the manifest's scenes and the manifest itself, sorted by project-relative path, each as its path, a zero byte, its size (u64, little endian) and its bytes. Text files have CRLF read as LF. Files whose names start with `.` are skipped and links are an error. Any content change, even a texture, makes builds incompatible in v1.

## Commands

What a client may ask the host, client to host in Command messages. IDs below 32 are the engine's. The host checks permission, target and rate (at most 20 per second, burst 10, per peer) and its own rules before acting.

### 32 `arena.request_team` (1 byte)

Sent by: any player. Rate: 2 per second, burst 2. Targets no entity. Accepted while the round is waiting, if that team has room.

| Offset | Field | Type | Allowed | Meaning |

| 0 | `team` | u8 | 0..1 | team |
