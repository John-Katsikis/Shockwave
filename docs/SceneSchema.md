# Shockwave scene schema

Generated by `player --schema` from the engine's component registry and this project's
assets. Regenerate it after adding components or assets; don't edit it by hand.

## File layout

```text
# Comments start with #.
shockwave_scene 2

entity "Stack"
  Transform
    position 0 0 0
end

entity "Upper crate"
  Transform
    position 0 1 0
  Parent
    entity "Stack"
  MeshRenderer
    mesh cube
    texture panel
end
```

- `entity "Name"` and `end` start at the left edge. Component names are indented two
  spaces, fields four. Names should be unique: links to other entities use them.
- A component line is the component name alone. Each field line is the field name and
  its value. Leave out fields to keep their defaults, and components to not have them.
- Values with spaces are quoted. Numbers use `.` for decimals.
- +Y is up, -Z is forward, units are meters. A Transform under a Parent is relative to it.
- Every playable scene needs one entity with a `Camera` (primary 1): the game looks
  through it.
- Lighting: a `Light` shines along its Transform's -Z (rotation -90 0 0 points straight
  down); position only matters for Point and Spot. Colors are linear. Intensity 1 lights
  a white surface facing the light to full white before exposure; a sun is usually 2 to
  4, a lamp 3 to 20. Point and Spot fall off to nothing at `range`. With no Light at all
  the renderer adds a default sun. The first `Environment` sets the light from all
  around (an `environment_map` panorama, ideally a .hdr file, or else the sky and
  ground colors), exposure (in stops) and tonemapper. See docs/Lighting.md.
- See a scene as the game renders it with `player --screenshot out.png --scene path`
  (`--view normals|lighting|unlit` to isolate a problem).
- Check a file with `player --check path/to/scene.swscene` (no path: every scene in the
  project). It prints one `file:line: problem` per issue and exits non-zero on any.

## Prefabs

A prefab is a reusable group of entities in a `.swprefab` file inside Content. It's
written like a scene with `shockwave_prefab 1` as its header line. Its first entity is
the root. Entities without a `Parent` hang under the root, and their Transforms are
relative to it. Prefabs can contain copies of other prefabs, but not of themselves.

To place a copy, give an entity a `Prefab` component with the file's path inside
Content. Then list only what this copy changes on the prefab's root, usually its
Transform. Every other value comes from the prefab:

```text
entity "Lamp by the door"
  Prefab
    path "Prefabs/Street lamp.swprefab"
  Transform
    position 4 0 -2
end
```

- The prefab's other entities are created under the copy when the scene loads. They
  aren't written in the scene. To change them, edit the prefab.
- New entities can go under a copy (`Parent` names the copy, or a part of it by name).
- `player --check` also checks every `.swprefab` in Content.

## Project manifest

`<Name>.swproject` sits at the project root; paths are relative to it and quoted.

```text
shockwave_project 1
name "My Game"
game_module "sample"      # must match the compiled gameplay library
startup_scene "Scenes/main.swscene"   # must exist
assets "Content"                      # optional, default Content
scenes "Scenes"                       # optional, default Scenes
theme "Config/Editor.swtheme"         # optional editor theme for this project
game_circuit "Content/Circuits/Game.swcircuit"   # optional; runs for the whole game (docs/Circuits.md)
tick_rate 60                           # simulation updates per second
window_size 1280 720
vsync true
audio_hrtf true                        # optional: false pans spatial sound for speakers
audio_hrtf_quality high                # optional: low or high
```

Unknown or repeated keys are errors. `player --check` validates the manifest too.
