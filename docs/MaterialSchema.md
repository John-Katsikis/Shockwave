# Material file reference (.swmaterial)

Generated by `player --material-schema` from the engine's material descriptors
(Source/Runtime/Assets/Private/Material.cpp). Don't edit by hand.

A `.swmaterial` file is UTF-8 text, one record per line. `#` starts a comment outside
quotes; strings are double-quoted with `\"` and `\\` escaped. Numbers are plain decimals
(a `.` for the point, whatever the system's locale). The first record is `swmaterial 1`.
Anything unknown, out of range, given twice or left over on a line is an error, with
its line number. Values a file doesn't set come from its parent, or from the defaults
below. Saving from the editor writes this canonical order and drops comments.

## Parent

| Record | Meaning |
|---|---|
| `parent "materials/base.swmaterial"` | Start from another material file |
| `parent "models/crate.glb" "Rusty metal"` | Start from a material imported with a model, found by name (so reordering the model's materials keeps it) |

Chains are at most 16 files long and can't loop. A missing parent draws the material magenta, with
the reason in the editor and `player --check`.

## Values

| Key | Values | Default | Range | Meaning |
|---|---|---|---|---|
| `family` | `standard` | standard | - | Shading family. standard is glTF's metallic-roughness; coat, skin and hair come later |
| `base_color` | r g b a | 1 1 1 1 | 0..1 | Linear RGB and alpha, multiplying the base_color texture |
| `metallic` | number | 0 | 0..1 | 0 plastic, wood, stone .. 1 bare metal; multiplies the metallic_roughness texture's blue |
| `roughness` | number | 0.5 | 0..1 | Perceptual roughness (not smoothness): 0 mirror .. 1 matte; multiplies the texture's green. 0 is kept as written; the shader never goes below 0.03 |
| `normal_scale` | number | 1 | 0..4 | How strongly the normal map tilts the surface |
| `occlusion_strength` | number | 1 | 0..1 | 0 ignores the occlusion map .. 1 full |
| `emissive` | r g b | 0 0 0 | 0..1000 | Light the surface gives off, linear RGB (above 1 for bright glows); multiplies the emissive texture |
| `alpha_mode` | `opaque`, `mask`, `blend` | opaque | - | opaque ignores alpha; mask cuts out below alpha_cutoff (in every pass, shadows included); blend is see-through |
| `alpha_cutoff` | number | 0.5 | 0..1 | mask's threshold |
| `double_sided` | `true` or `false` | false | - | Draw back faces too (leaves, cloth, glass panes) |
| `detail_strength` | number | 1 | 0..1 | How much of the detail layer shows, times detail_mask and the fade |
| `detail_normal_scale` | number | 1 | 0..4 | How strongly the detail normal map tilts the surface |
| `detail_roughness` | number | 0.5 | 0..1 | The roughness the detail layer moves the surface towards... |
| `detail_roughness_strength` | number | 0 | 0..1 | ...and how far (0 leaves roughness alone) |
| `detail_mask_channel` | `r`, `g`, `b`, `a` | r | - | Which channel of the detail_mask texture limits the detail |
| `detail_fade` | 2 numbers | 0 0 | 0..1e+05 | Metres from the camera where the detail starts and finishes fading out, smoothly; 0 0 never fades |
| `layer_mask` | `texture_r`, `texture_g`, `texture_b`, `texture_a`, `vertex_r`, `vertex_g`, `vertex_b` | texture_r | - | Where the second layer shows: a channel of the layer_mask texture, or a colour channel of the vertices (whose colours then don't tint the surface) |
| `layer_base_color` | r g b a | 1 1 1 1 | 0..1 | The second layer's linear RGB (alpha unused: cut-outs follow the first layer) |
| `layer_metallic` | number | 0 | 0..1 | As metallic |
| `layer_roughness` | number | 0.5 | 0..1 | As roughness |
| `layer_normal_scale` | number | 1 | 0..4 | As normal_scale |

## Texture slots

| Record | Meaning |
|---|---|
| `texture <slot> "textures/x.png"` | The slot's texture: an image or .ktx2 in Content |
| `clear_texture <slot>` | Removes a texture the parent has |
| `uv_set <slot> 0` | Which UV set: 0 (TEXCOORD_0) or 1 (TEXCOORD_1) |
| `uv_transform <slot> offsetU offsetV scaleU scaleV rotationRadians` | `uv' = offset + R(rotation) (scale uv)`, as glTF's KHR_texture_transform |
| `sampler <slot> wrapU wrapV min mag mip anisotropy` | wrap repeat, clamp or mirror; min and mag linear or nearest; mip none, nearest or linear; anisotropy 1..16 (the graphics setting caps it) |

| Slot | Decoded as | Holds |
|---|---|---|
| `base_color` | colour (sRGB) | Colour and alpha (sRGB) |
| `normal` | data (linear) | Tangent-space normals, green up (linear) |
| `metallic_roughness` | data (linear) | Green roughness, blue metallic (linear, glTF's packing) |
| `emissive` | colour (sRGB) | Emitted colour (sRGB) |
| `occlusion` | data (linear) | Red darkens ambient light only (linear) |
| `detail_color` | colour (sRGB) | Multiplies the base colour around neutral white: 1 1 1 changes nothing (sRGB) |
| `detail_normal` | data (linear) | Fine normals composed on top (linear) |
| `detail_mask` | data (linear) | Where the detail shows; detail_mask_channel (linear) |
| `layer_mask` | data (linear) | Where the second layer shows; layer_mask (linear) |
| `layer_base_color` | colour (sRGB) | The second layer's colour (sRGB) |
| `layer_normal` | data (linear) | The second layer's normals (linear) |
| `layer_metallic_roughness` | data (linear) | The second layer's roughness and metallic (linear) |

A texture is decoded the way its slot says, whatever another material does with the same
image: one used as colour by one material and as data by another is kept twice.

## Detail and second layer

The detail layer is on when `detail_color` or `detail_normal` has a texture and
`detail_strength` is above 0; it tiles with its own `uv_transform` (scale 8 8 repeats it
eight times). The second layer is on when `layer_mask` reads the vertex colours, or the
`layer_mask` slot has a texture. At `material_quality low` the detail layer is left out;
masks, second layers and alpha never are.
